# 掼蛋（Guandan）教学型纯前端网页游戏 · 调研与设计方案

> 勘误：用户所述「灌蛋」的规范名称为「**掼蛋**」（guàn dàn）。
> "掼"在淮安方言中意为"摔、砸"，"掼蛋"即打牌人将手中"蛋"（炸弹）砸向桌面的动作。
> 本文档全部按「掼蛋」调研与设计。

---

## 0. 结论摘要

1. **正宗规则基线**：以国家体育总局棋牌运动管理中心 2017 年发布的《淮安掼蛋竞赛规则》（国标）为基线，参照 2022《竞技掼蛋竞赛规则（试行）》与 2023《江苏省掼蛋竞赛规则》做差异标注；民间/线上平台变体单独列出，不混入主规则。
2. **教学产品形态**：单机纯前端网页游戏（无后端、无账号），Vue 3 + TypeScript + Vite，规则引擎与 AI 与 UI 严格分层；进度存 localStorage；PWA 支持手机/平板添加到主屏幕离线练习。
3. **AI 分五级**（随机合法 → 贪心 → 启发式记牌 → 配合协作 → 蒙特卡洛模拟），玩家段位与 AI 等级联动，实现"打赢当前级别的对家才能晋级"的成长引导。
4. **发布**：用户所述 "Claudefare" 应为 **Cloudflare**。2026 年 Cloudflare 官方推荐新项目使用 **Workers（静态资源托管）** 而非 Pages；一条 `wrangler deploy` 即可上线，静态资源请求免费。注意 `*.workers.dev` / `*.pages.dev` 在中国大陆常不可达，需绑定自有域名并实测（详见 §7.3）。

## 1. 规则体系调研与对比（广泛调研，深入对比）

掼蛋起源于 1960 年代江苏省淮安县南闸公社（今淮安市淮安区），由"跑得快"和"八十分（升级）"演化而来，2014 年列入淮安市非物质文化遗产。经查证，目前存在多套规则文本，权威度与用途各不相同：

| 规则文本 | 发布方 / 年份 | 定位 | 关键点 |
|---|---|---|---|
| 《淮安掼蛋竞赛规则》 | 国家体育总局棋牌运动管理中心，2017-04-15 发布，人民体育出版社出版 | **国标，最"正宗"的统一基线** | 统一术语（"木板"→三连对、"杂花顺"→顺子、"火箭"→同花顺），规定 8 种赛制，明确违规判罚 |
| 《竞技掼蛋竞赛规则（试行）》 | 体育总局棋牌中心，2022 年底 | 竞技体育化版本 | 计时计副制（如每轮 50 分钟限打 9 副），先过 A 或级数高者胜；报牌限一次；违例/犯规/判负三级处罚 |
| 掼牌（掼蛋）系列制度 | 体育总局棋牌中心，2023 | 项目更名"掼牌（掼蛋）"后的赛事纪律准则与处罚规定等配套制度 | 用于全国掼牌（掼蛋）公开赛等官方赛事 |
| 《江苏省掼蛋竞赛规则（2023）》 | 江苏省社会体育管理中心 | 省级现行规则 | 继承 2017 简易规则主体；允许"在一定范围和阶段的比赛中取消报牌" |
| DB3208/T 235-2025《群众体育智力运动 掼蛋 比赛规则》 | 淮安市地方标准，2025-05-02 实施 | 最新的地方标准化文本 | 与 DB3208/T 173-2022《掼蛋 术语与定义》配套 |
| 民间/线上平台规则 | 各地、各棋牌平台 | 日常玩法 | 与国标存在若干差异（报牌张数、还贡限制、抗贡条件、冲A失败处理等），见 §3.9 差异表 |

**对比结论**：核心玩法（牌型、大小、升级、贡牌）各版本高度一致；差异集中在**还贡限制、报牌张数、冲A失败处理、抗贡变体、判罚细则**这几处边缘规则。教学游戏应以 2017 国标为默认规则，把差异点做成"规则开关"（设置项），既正宗又兼容各地习惯。

## 2. 正宗详细规则（以 2017 国标为基线）

### 2.1 牌具、人员与座次

- 两副标准扑克共 **108 张**（含 4 张王），四人对局，**对门（对家）为同伴**，两两一队。
- 每人 **27 张**（一手牌）。抓牌、出牌均按**逆时针**方向进行。
- 术语：本家、对家（搭档）、上家、下家；出完牌次序依次为**头游（上游）、二游、三游、末游（下游）**。
- 同队两人分获头游、二游，称为**双下**（对方两人均未出完，一副牌自然结束）。

### 2.2 级牌与逢人配

- 每局第一副从 **打 2** 开始，当前级数对应的牌称**级牌（主牌）**。
- 单张大小（以打 10 为例）：**大王 > 小王 > 级牌(10) > A > K > Q > J > 9 > 8 > 7 > 6 > 5 > 4 > 3 > 2**。
- **逢人配（红心级牌，又称红心参谋/百搭）**：两张红心级牌可以充当**除大小王外**的任意牌，参与组成任意牌型（不能组四王炸）。这是掼蛋最具特色的规则，极大丰富了技战术组合。
  - 逢人配单独打出时，按级牌本身的身份与大小计算。
  - 逢人配**不得用于进贡**。
- 级牌参与顺子/连对/三同连张时按其**自然点数**排序（打 10 时，8-9-10-J-Q 中的 10 只是普通的 10），级牌只有在按单张点数比大小时才高于 A。

### 2.3 牌型定义（国标术语）

| 牌型 | 定义 | 示例（打 10） |
|---|---|---|
| 单张 | 一张牌 | 大王 |
| 对子 | 两张同点 | ♠9♦9 |
| 三同张 | 三张同点 | 888 |
| 三带二 | 三同张 + 一个对子 | 999 + 44 |
| 三连对（俗称木板） | 三对**点数相连**的对子 | 445566；AA2233（A 作 1）；QQKKAA |
| 三同连张（俗称钢板） | 两组**点数相连**的三同张 | 555666；AAA222（A 作 1） |
| 顺子（俗称杂花顺） | 五张（且只能五张）相连单牌，花色不限 | 45678；A2345；10JQKA |
| 同花顺（俗称火箭） | 五张同花色相连 | ♥10JQKA |
| 炸弹 | 四张及以上同点数牌（可含逢人配） | 7777；6666+两张红心10（六炸） |
| 四大天王（四王炸） | 两大王 + 两小王 | 最大牌 |

- **A 的双重性**：A 在三连对、三同连张、顺子、同花顺中可作 1（最小，如 A2345、AA2233、AAA222），也可作最大（10JQKA、QQKKAA、KKKAAA）。**不可跨 A 循环**（KA2、QKA2 之类不连）。

### 2.4 牌型大小（压牌规则）

1. 领出者可出任意合法牌型；跟牌者**只能出同牌型同张数**且点数更大的牌 —— **除非**出炸弹类（炸弹、同花顺、四王）。
2. 炸弹类内部排序：
   **四大天王 > 六张及以上炸弹 > 同花顺 > 五张炸弹 > 四张炸弹**
   - 炸弹之间：张数多者大；张数相同比点数。
   - 同花顺之间：只比最大牌点数，不比花色。
   - 借助逢人配，理论最大普通炸弹为 8 同点 + 2 逢人配 = **十炸**（仅次于四王）。
3. 普通牌型内部：以牌点大者为大；**三带二只比较三同张部分**（999+33 > 888+AA）。
4. 一圈牌：连续三家过牌（"过"/"不要"或敲桌示意），该圈结束，最后出牌者领出下一圈。

### 2.5 流程（一副牌）

1. **首出确定**：一局的第一副，中间随机翻一张牌（翻到大小王或红心级牌须重翻），抓到该牌者首圈领出。之后每副由贡牌关系决定首出（见 §2.7）。
2. **洗切**：由上游方洗牌，下游方切牌，下游先抓牌（双下时由上游的下家先抓）。
3. 逆时针依次出牌/压牌/过牌，直至三人出完，产生头游~末游；**双下时一副牌自然提前结束**。
4. **接风**：某玩家打出**最后一手牌**后，其余三家都不压，则下一圈由其**对家**领出（早期规则曾由下家领出，现行规则为对家接风）。

### 2.6 升级与过 A

- 每副结束按头游同伴的名次升级：**同伴二游（双下）升 3 级；同伴三游升 2 级；同伴末游升 1 级**。下一副以赢家新级数为级牌。
- 级数序列：2→3→…→K→A→过A，共 14 级。**A 级必打**（升级冲过 A 的仍按 A 计）。
- **过 A 条件**：打 A 级的一方须本队一人头游、且**同伴不是末游**（即头游+二游或头游+三游，俗称 1-2 过 / 1-3 过），方为过 A 获胜。
- 民间常见变体（非国标必选）："冲 A 失败三次退级" —— 打 A 级连续三副均未过 A（同伴皆末游），退回 2 级重打。
- 竞技规则采用**计时计副制**：限时/限副内先过 A 者胜；均未过 A 则级数高者胜；级数相同加打一副决胜。

### 2.7 进贡、还贡、抗贡（从第二副开始）

**进贡**
- 单下（对方仅一人末游）：末游向头游进贡一张牌，必须是手中**最大的牌（逢人配除外）**。
- 双下：两名末游各进贡一张最大的牌；**大者给头游，小者给二游**，还贡对应"拿谁的还谁"。若两张贡牌同点，按**顺时针方向**进贡（部分线上平台改为随机分配）。
- 若手中最大牌有多张并列（非王），进贡方可自选贡哪一张（存在"微调"策略空间）。

**还贡**
- 受贡者须还一张牌给进贡者。国标/竞赛系规定：**还给己方搭档的牌必须 ≤10（含 10）；还给对方的牌可为任意牌**（同伴末游进贡给你时才触发"还同伴"情形）。
- 民间简化规则常一律限定"还贡不得大于 10"。两种口径都应做成规则开关。

**抗贡**
- 单下：末游抓到**两张大王**，免贡。
- 双下：两名末游**合计持有两张大王**（各一张、或一人两张），免贡。
- 抗贡时须亮出大王（竞技/线上要求），由**头游**首圈领出。
- 个别地区流传"持炸弹可抗贡"，**非国标**，默认不采用。

**贡后首出**
- 单下且进贡：由**进贡者（末游）**领出。
- 双下且进贡：由**贡大牌者**领出；两贡同大时由**头游的下家**领出。
- 抗贡：由**头游**领出。

### 2.8 报牌

- 出牌后手中剩余 **≤10 张**应报牌（国标/江苏系；南京等地民间为 ≤6 张）。
- 竞技规则：报牌只允许一次，其他人未听清可立即询问，之后仅在本人获得出牌权时可问一次；反复报牌/追问给予警告。
- 江苏省 2023 规则允许"在一定范围和阶段的比赛中取消报牌"。

## 3. 特殊条件与案例集（可直接转化为单元测试用例）

以下案例覆盖规则引擎最容易写错的边界，编号即建议的测试用例 ID。

### 3.1 逢人配（Wild）案例
- **W1** 打 10，手持 2,3,4,6 + 红心10 → 红心10 替 5，组成顺子 23456。合法。
- **W2** 打 9，♠9♥9 + 10,Q,K → 红心9 替 J，组成顺子 9 10 J Q K（♠9 为自然 9）。合法。
- **W3** 打 6，♥6 + ♠7♠8♠9♠10 → 红心6 替 ♠J（或 ♠6），组成**同花顺**（逢人配配同花顺时视为该花色）。合法。
- **W4** 66666666 + 两张红心级牌 → **十炸**，压除四王外一切牌。合法。
- **W5** 红心级牌 + 大王大王小王 → 组四王？**非法**（逢人配不能配王、不能组四王）。
- **W6** 单出红心级牌 → 按级牌计（大于 A，小于小王）。
- **W7** 进贡时贡红心级牌 → **非法**（逢人配不在进贡之列），须贡除它之外最大的牌。

### 3.2 A 与顺序案例
- **A1** A2345 合法（A=1，为最小顺）；10JQKA 合法（最大顺）。
- **A2** JQKA2 / QKA23 → **非法**（不可跨 A 循环）。
- **A3** AA2233、QQKKAA 合法三连对；KKAA22 → **非法**。
- **A4** AAA222 合法三同连张（A=1）；KKKAAA 合法（A 最大）。
- **A5** 顺子固定五张：456789 六张 → **非法**牌型。

### 3.3 比较与压牌案例
- **C1** 999+33 压 888+AA（三带二只比三张）。
- **C2** 同花顺 ♦34567 压 五炸 KKKKK？→ ♦34567 是同花顺，**压任意五张炸弹**。反之 666666（六炸）压任意同花顺。
- **C3** 同花顺 ♥10JQKA vs ♠10JQKA → 同点同大，后者**不能压**前者（同花顺不比花色）。
- **C4** 打 7 时单张 7（非红心）压单张 A（级牌大于 A）。
- **C5** 打 7 时顺子 56789 vs 45678：正常比点（顺内 7 为自然 7）。
- **C6** 跟牌只能同型同张数：领出三连对 445566，跟 778899 合法，跟 777888（钢板）**非法**（除非炸弹类）。

### 3.4 流程案例
- **F1** 接风：A 打出最后一手 33，B/C/D 皆过 → 下一圈由 **A 的对家**领出。
- **F2** 双下自然结束：同队两人先后出完（头游+二游），第三、四名不再决出，两名对手均按末游处理，各自进贡。
- **F3** 首副翻牌翻到大王/小王/红心级牌 → 打乱重翻。

### 3.5 贡牌案例
- **T1** 单下，末游手牌最大为大王 → 贡大王；头游还牌（还对方任意 / 民间口径 ≤10，按开关）。
- **T2** 双下，两末游各贡：一贡大王、一贡小王 → 大王给头游、小王给二游；头游还给贡大王者，二游还给贡小王者；**贡大王者首圈领出**。
- **T3** 双下，两贡同为红桃A与黑桃A（同点）→ 按顺时针方向进贡；首圈由**头游的下家**领出。
- **T4** 抗贡：双下两末游各持一张大王 → 亮王免贡，头游领出。
- **T5** 升 1 级情形（头游+末游同队）：末游是头游的**同伴**，仍进贡；还贡触发"还同伴 ≤10"限制（国标口径）。
- **T6** 手持两张并列最大牌（如双♠A，非王）→ 进贡方可自选其一（策略：贡出与自己同花相邻牌多的那张，降低对方组同花顺概率）。

### 3.6 过 A 案例
- **G1** 打 A 级，头游+同伴三游 → 过 A，获胜。
- **G2** 打 A 级，头游+同伴末游 → **未过 A**，级数仍为 A，下副继续打 A。
- **G3** （变体开关）打 A 连续三副 G2 情形 → 退回 2 级。

### 3.7 判罚案例（竞技模式可选实现）
- **P1** 出错牌/带落牌（暴露张）：领出方收回重出（由左手方指定牌型）；跟牌方收回并停出一轮。
- **P2** 出错牌者的搭档获得下一轮领出权时，不得领出因暴露张形成的可压牌型（唯此一手除外）。
- **P3** 不应贡牌者亮出了最大张 → 首次轮到出单张时必须先出该张。

### 3.8 数量守恒不变量（仿真校验用）
- 任意时刻：四家手牌 + 已出牌 + 贡还在途 = 108 张，无重复。
- 每种点数（除王）恰 8 张、大小王各 2 张。

### 3.9 国标 vs 常见民间/平台差异对照

| 差异点 | 2017 国标 / 竞赛系 | 常见民间 / 线上平台 | 本游戏处理 |
|---|---|---|---|
| 还贡限制 | 还同伴 ≤10，还对方任意 | 一律 ≤10 | 规则开关，默认国标 |
| 报牌张数 | ≤10 张报牌 | 南京等地 ≤6，或不报 | 开关，默认 10 |
| 冲A失败 | 计时计副制内自然处理 | 三次未过退回 2 级 | 开关，默认关闭 |
| 抗贡条件 | 仅双大王 | 个别地区允许炸弹抗贡 | 仅实现双大王 |
| 双贡同大 | 顺时针进贡 | 平台随机分配 | 默认顺时针 |
| 接风对象 | 对家 | 早期规则下家 | 固定对家 |

## 4. 教学游戏设计：从小白到合格掼蛋玩家

### 4.1 设计哲学

掼蛋"学会很容易，打好非常难"，是典型的不完全信息四人协作博弈（"七分牌力，三分配合"）。教学系统按**技能拆解 → 微练习 → 陪练对局 → 段位晋升**四层递进，每个技能点都有独立的可练、可测、可反馈闭环，而不是把小白直接扔进完整对局。

### 4.2 技能地图（课程即关卡）

| 阶段 | 技能点 | 练习形式 | 通关判定 |
|---|---|---|---|
| L0 识牌 | 10 种牌型识别、级牌概念 | 闪卡式判型小测（"这是什么牌型？"） | 20 题 ≥ 90% |
| L1 压牌 | 合法跟牌、炸弹压制链 | "能不能压？出哪手？"即时判题 | 连续 15 题正确 |
| L2 组牌 | 27 张手牌最优拆组、拆牌代价 | 给定手牌，拖拽组牌，与引擎最优解比对评分 | 得分 ≥ 80 |
| L3 逢人配 | 百搭的 6 种典型用法（补顺/补炸/补同花顺/留单/组钢板/组木板） | 专项谜题（每题指定"用红心级牌凑出最强一手"） | 12 题全对 |
| L4 贡牌 | 进贡微调、还贡选牌、抗贡判断 | 情境题 + 半局模拟 | 情境题 ≥ 85% |
| L5 记牌 | 大王/级牌/炸弹计数，"外面还剩几张？" | 对局中随机暂停提问；可开关记牌器辅助 | 抽查正确率 ≥ 70% |
| L6 配合 | 让牌送牌、顶上家放下家、保对家头游 | 剧本残局（固定四家手牌的经典局面） | 残局通关 |
| L7 残局 | 冲游时机、"枪不打四"、逢五出对等定式 | 残局挑战库（类象棋残局，10~30 关） | 通关数解锁段位 |

配套将掼蛋口诀融入提示语：**"情况不明，对子先行"、"逢五出对"、"枪不打四"** 等，在教练模式中于对应局面弹出讲解。

### 4.3 AI 对手分级（与玩家段位联动）

纯前端可行的五级 AI，全部实现为同一策略接口 `Strategy.decide(view: PlayerView): Action`：

| AI 等级 | 对应玩家段位 | 策略 | 实现要点 |
|---|---|---|---|
| Lv1 新手 | 学徒 | 随机合法出牌；能压则压最小 | 合法动作枚举 + 随机/最小选择 |
| Lv2 入门 | 牌手 | 贪心 + 手牌评估：出牌后剩余手数最少、拆牌代价最小 | 手牌分解器（把 27 张分解为最少手数的组合）+ 简单估值 |
| Lv3 进阶 | 好手 | 启发式 + 记牌：统计已出牌，估算对手剩余大牌；控牌定式（逢五出对、留炸时机） | 明牌计数表 + 规则化策略树 |
| Lv4 高手 | 强手 | 协作意识：识别同伴强弱，让牌/送牌/顶上家；贡还牌策略 | 在 Lv3 上加队友建模与角色分工（主攻/助攻） |
| Lv5 大师 | 掼神 | 确定化蒙特卡洛：按已知信息随机补全三家暗牌 N 次，用 Lv3 策略 rollout，选平均胜率最高动作 | 放 **Web Worker** 后台计算，避免卡 UI；N≈50~200 可在手机上秒级完成 |

**段位晋升机制**：玩家对局默认三个 AI 均为当前段位对应等级；近 20 局胜率 ≥ 55% 且完成该段位技能课，即晋升，AI 同步升级。晋升赛制造仪式感（三局两胜）。

### 4.4 教练系统（引导式反馈）

- **出牌前建议**（可开关）：高亮引擎推荐的一手并给一句理由（"上家报 3 张，出对封锁单牌口"）。
- **出牌后复盘**：偏离推荐较大时标记"值得商榷"，局末生成 3 条关键手复盘。
- **记牌器**：分等级开放 —— 学徒段全开（王/级牌/炸弹全显示），随段位逐步收起，倒逼玩家自己记牌。
- **失误热力**：本地统计玩家在各技能点的失误率，推荐回炉对应 L0~L7 练习。

### 4.5 数据与进度（无后端）

全部存 `localStorage`（或 IndexedDB）：段位、课程进度、对局统计、残局通关记录、规则开关。提供"导出/导入存档"（JSON 文件下载/上传），换设备可迁移，完全不需要账号后端。

## 5. 技术方案（Vue 3 纯前端）

### 5.1 选型（契合 Python/Vue/Go/Rust 主力生态偏好）

- **框架**：Vue 3（`<script setup>` + Composition API）+ TypeScript + Vite + Pinia（状态）
- **渲染**：DOM + CSS 即可（扑克是 2D 卡片 UI，无需 Canvas/WebGL；动画用 CSS transition + FLIP）
- **测试**：Vitest（引擎单测）+ Playwright（端到端，可选）
- **AI 重计算**：Web Worker（Lv5 蒙特卡洛）
- **PWA**：`vite-plugin-pwa`（manifest + Service Worker 离线缓存）

### 5.2 架构分层（关键：引擎与 UI 解耦）

```
src/
├── core/            # 纯 TS 规则引擎，零框架依赖，可在 Node 里跑仿真
│   ├── card.ts      # 牌编码：0..107 → {rank, suit, deck}
│   ├── pattern.ts   # 牌型识别/枚举（含逢人配）
│   ├── compare.ts   # 压牌合法性与大小比较
│   ├── deal.ts      # 洗牌(可注入种子RNG)、发牌
│   ├── tribute.ts   # 进贡/还贡/抗贡状态机
│   ├── game.ts      # 一副牌状态机 + 一局升级逻辑
│   └── rules.ts     # 规则开关（§3.9 差异项）
├── ai/
│   ├── strategy.ts  # 策略接口 + PlayerView（只暴露该家可见信息!）
│   ├── lv1..lv4.ts
│   └── lv5.worker.ts
├── coach/           # 教学：题库、残局库、复盘、口诀提示
├── stores/          # Pinia：对局、进度、设置
└── ui/              # Vue 组件：牌桌、手牌、出牌区、报牌气泡…
```

设计要点：
- `PlayerView` 只包含该玩家可见信息（自己手牌、各家已出牌、剩余张数、级数、贡牌记录），**AI 不允许读全局暗牌** —— 这既是公平性，也让 Lv5 的"确定化补全"有意义。
- 引擎全部纯函数 + 显式状态对象，动作日志（`ActionLog: Action[]`）即牌局录像，天然支持复盘/回放/断点续玩（存 localStorage）。
- 随机数用可注种子的 PRNG（如 mulberry32），bug 可用种子 100% 复现。

### 5.3 核心算法：含逢人配的牌型识别

逢人配是引擎最大难点。推荐做法：

1. 数出所选牌中的逢人配张数 w（0/1/2），其余为固定牌。
2. 对每种候选牌型（单/对/三/三带二/顺/同花顺/三连对/钢板/炸弹），写"给定固定牌 + w 张百搭能否成型、成型后关键点数是多少"的判定函数（组合数极小，直接枚举替代值 2..A 与四花色即可，无性能压力）。
3. 识别结果统一为 `{type, size, keyRank, cards}`，比较函数只看 `type/size/keyRank`。
4. **AI 用的"手牌分解器"**：把 27 张分解为手数最少/价值最高的组合集（贪心 + 局部回溯足够；逢人配枚举其最优归属）。这是 Lv2+ 所有策略与 L2 组牌课的共用底座。

### 5.4 对局状态机

```
LEVEL_START → DEAL → (第2副起) TRIBUTE{进贡→还贡|抗贡} → FIRST_LEAD
→ TRICK 循环{领出→跟/过×3} → 玩家出完→名次登记 → 双下?提前结束
→ DEAL_END → SCORE(升级/过A判定) → 下一副 | GAME_END
```

每个迁移都由 `applyAction(state, action) → state'` 完成，非法动作抛错并被 UI/测试捕获。

### 5.5 移动端/平板适配

- 竖屏优先布局：对家在上、上下家居两侧、自家手牌扇形铺底；768px+ 平板加宽出牌区。
- 触摸交互：点选/滑动多选牌，选中上浮；长按看大图；出牌按钮 ≥ 44px 触控热区。
- `viewport-fit=cover` + 安全区 inset，禁双击缩放；`visualViewport` 处理软键盘（本游戏基本无输入框，影响小）。
- PWA：manifest（名称/图标/`display: standalone`）+ SW 预缓存全部静态资源 → **加过主屏后地铁里离线也能练**。

## 6. 调试与测试方法

1. **引擎单测优先**：§3 的每个案例编号（W1~P3）直接落为 Vitest 用例，规则改动即回归。目标：`core/` 覆盖率 ≥ 90%。
2. **自对弈仿真**：Node 脚本让 AI×4 快速打上万副（引擎无框架依赖所以可行），每步校验 §3.8 守恒不变量与动作合法性；同时统计各级 AI 胜率矩阵，验证"Lv(n+1) 对 Lv(n) 胜率显著 > 50%"，即难度梯度真实存在。
3. **种子复现 + 录像回放**：任何异常局面记下 `{seed, actionLog}`，一键重放到出错步；开发面板支持"上帝视角"看四家手牌、手动摆残局。
4. **UI 调试**：Vue DevTools 看 Pinia 状态；真机调试用 Chrome remote debugging / Safari 联机，或临时注入 vConsole 看移动端日志。
5. **LLM 辅助（Vibe Coding 流程）**：先让 Claude 依据本文件 §2/§3 生成 `core/` + 全量测试 → 跑测试红转绿 → 再生成 UI。规则文档即 prompt，测试即验收标准。

## 7. 发布到 Cloudflare（勘误：Claudefare → Cloudflare）

### 7.1 2026 年现状：优先 Workers 静态资源，而非 Pages

- Cloudflare 已官宣：Workers 现已支持直接托管静态资源与 SSR，**新项目应从 Workers 开始**；Pages 继续受支持，但后续投入与新特性都集中在 Workers。
- 两者定价已拉平：静态资源请求在两个平台上均免费；纯静态 SPA 在免费额度内即可长期运行。
- 已有 Pages 项目无需迁移；但本项目是新建，直接走 Workers 静态资源路径。

### 7.2 部署步骤（纯静态 SPA，三分钟上线）

```bash
# 方式一：官方脚手架（自动配好 Cloudflare Vite 插件）
npm create cloudflare@latest guandan-trainer -- --framework=vue

# 方式二：已有 Vite+Vue 项目，只加一个配置文件 wrangler.jsonc：
# {
#   "name": "guandan-trainer",
#   "compatibility_date": "2026-07-01",
#   "assets": {
#     "directory": "./dist",
#     "not_found_handling": "single-page-application"
#   }
# }

npm run build          # vite build → dist/
npx wrangler login     # 首次：浏览器授权 Cloudflare 账号
npx wrangler deploy    # 上传 dist/，得到 https://guandan-trainer.<你>.workers.dev
```

- `not_found_handling: "single-page-application"` 让所有未命中路径返回 index.html（SPA 路由必需）。
- 持续部署：把仓库连到 **Workers Builds**（GitHub push 自动构建部署，分支有 preview URL），或本地 `wrangler deploy` 手动发。
- 若纯资源无 Worker 脚本，配置里不要放 `main`/ASSETS binding。

### 7.3 中国大陆访问风险（重要，需实测）

- `*.workers.dev` 与 `*.pages.dev` 子域在大陆长期存在 DNS 污染/阻断，**手机直连大概率打不开** —— 这一点必须在选型时预先考虑（此为社区普遍经验，建议部署后用大陆网络实测确认）。
- 缓解路径（按成本递增）：
  1. **绑定自有域名**并走 Cloudflare 代理（大陆可达性通常好于 workers.dev，但速度不稳定，需实测）；
  2. 同一份 `dist/` 双发到国内静态托管（如腾讯 EdgeOne Pages 等）做大陆入口，Cloudflare 做海外入口；
  3. 若面向大陆正式运营，最终仍需 ICP 备案 + 国内 CDN。
- 纯前端游戏的好处：`dist/` 是普通静态文件，**换任何托管平台零改动**，先 Cloudflare 快速上线验证，再按访问数据决定是否加国内镜像。
